# Common Mistakes in the Amazon Interview

The most commonly reported reason for an Amazon rejection is weak behavioral answers, not weak code. The ten mistakes below are specific to the Amazon process. Each one has a direct correction.

The behavioral questions are built on the Leadership Principles, the 16 statements that describe how Amazon expects employees to act.

## The ten mistakes

| # | Mistake | Why it costs the candidate | Correction |
|---|---|---|---|
| 1 | Preparing for one behavioral interview | Every interviewer asks behavioral questions | Prepare 10 to 12 stories before the loop |
| 2 | Telling stories without numbers | Interviewers write down evidence, and a number is the clearest evidence | Put one measured result in every story |
| 3 | Saying "we" for every action | The notes then contain no evidence about the candidate | Say "I" for your own decisions and actions |
| 4 | Repeating one story across interviews | Interviewers compare notes in the debrief | Map stories to principles and use each story once |
| 5 | Using the full hour for code | Behavioral questions take 10 to 15 minutes of a coding interview | Practice every problem at 30 minutes |
| 6 | Writing pseudo code | Amazon asks for code that compiles in a real language | Finish with code that runs, then improve it |
| 7 | Treating the survey sections as unimportant | Each section of the online assessment must be passed separately | Read the principles before the assessment and answer consistently |
| 8 | Designing only for growth | Failure cases are graded as well as scale | Name two failure cases in every design |
| 9 | Ignoring cost and operations | Frugality is a principle, and engineers run their own services | State one cost decision and one monitoring decision |
| 10 | Trying to identify the Bar Raiser | Candidates are not told who it is | Prepare every interview to the same standard |

## The mistakes in more detail

**Stories that stop at the first answer.** The Bar Raiser is a trained interviewer from outside the hiring team, and that interview contains many follow-up questions. A candidate who knows only the summary of a story cannot answer the third question. Prepare the numbers, the other person's view, and the change you would make.

**A missing bracket in the assessment.** Candidates report that both coding questions must compile before the next section opens. Leave the code in a state that runs at all times, and write the slow correct solution first.

**Inconsistent survey answers.** Similar statements appear more than once in different words. A candidate who chooses "collect more data" once and "act at once" in a similar case appears inconsistent.

**A design with every technology.** Adding components without a requirement behind them is a commonly reported error. Start with a simple design and add a component only when a requirement needs it.

**No target level.** The level is set from the loop and is rarely changed afterward. Ask the recruiter for the target level before the loop is scheduled. See [levels](levels.md).

**An unprepared motivation answer.** "Why Amazon?" is reported in almost every loop. An answer written in advance is specific, and an improvised answer is usually general.

## A check before the loop

1. Ten or more stories, each mapped to two principles.
2. A number in every result.
3. Three follow-up answers prepared for each story.
4. Medium coding problems solved in 30 minutes.
5. One design practiced with numbers, failure cases, and cost.
6. A written answer to "Why Amazon?"
